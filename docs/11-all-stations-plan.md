# 全443駅を詳細データにする計画

方針決定: **掲載候補の443駅すべてを詳細データにする。** 一部を駅名だけで留める案は採らない。

この文書は、その決定が実際に何を要求するかを数字で示し、どう進めるかを決めるためのもの。

---

## 1. 何が必要なのか（数量）

443駅に対して埋めるべき値の総数。

| 項目 | 1駅あたり | 総数 |
|---|---|---|
| 所在区・路線 | — | 443 ✅ 完了 |
| 所要時間（7オフィス街） | 7 | 3,101 ✅ 完了 |
| スコア | 16軸 | 7,088 |
| 家賃相場 | 4間取り | 1,772 |
| 周辺施設 | 数件 | — |
| 散文（日本語） | 5項目 | 2,215 |
| 散文（他言語） | 5項目 × 言語数 | 2,215 × N |

散文5項目は tagline / summary / goodFor / notFor / residentComment。

---

## 2. 誰が埋めるのか（層別）

**443駅は手書きでは埋まらない。** 埋め方を層に分け、人間は人間にしかできない層に集中させる。

| 層 | 対象 | 埋め方 | 状態 |
|---|---|---|---|
| L1 事実 | 駅名・所在区・路線 | 公開データから機械生成 | ✅ 443/443 |
| L2 計算 | 所要時間、commute、transitConvenience | 鉄道networkの最短経路と路線構成から計算 | ✅ 443/443 |
| L3 購入 | 家賃4間取り、rentValue | 商用の賃料統計を購入 | ⬜ 12/443（推定値） |
| L4 一次データ | 施設系6軸、safety、nature | POI・犯罪統計・公園データから機械生成 | ⬜ 12/443（推定値） |
| L5 判断 | quietness、style、family、singleLife、internationalFriendliness | 人間の土地勘 | ⬜ 12/443（推定値） |
| L6 散文 | 各駅の説明と在住者コメント | 日本語は人間、他言語はAIローカライズ＋レビュー | ⬜ 12/443（仮テキスト） |

現在の充足率は `npm run validate:data` が毎回表示する。

### 16軸の内訳

| 層 | 軸 |
|---|---|
| L2 計算（完了） | `commute` `transitConvenience` |
| L3 購入 | `rentValue`（家賃と通勤時間から算出） |
| L4 一次データ | `shopping` `food` `cafe` `nightlife` `healthcare` `fitness` `safety` `nature` |
| L5 人間の判断 | `quietness` `family` `singleLife` `internationalFriendliness` `style` |

**機械で8軸、購入で1軸、人間は5軸。** 人間が判断する軸を5つに絞れたことが、443駅を現実的にしている。

## 3. 一番の難所は散文

L1〜L5 は仕組みで解ける。**解けないのは L6、とくに在住者コメント。**

在住者コメントは構想 §4.2 の差別化の中核で、AI に書かせた時点でこのサービスの存在理由が消える。

### 規模

日本語の在住者コメントを443駅ぶん書くと:

| 執筆ペース | 所要 |
|---|---|
| 1日5駅 | 89営業日（約4.5か月） |
| 1日10駅 | 45営業日（約2か月） |
| 1日3駅 | 148営業日（約7か月） |

書き手1人での試算。実際には土地勘のない駅を調べる時間が加わる。

### 現実的な進め方

1. **区ごとにまとめて書く。** 駅を跨いで移動しながら書くより、同じ区を続けて書くほうが比較の質が上がり、速い。隣接駅との違いを書けるのがこのサービスの価値なので、まとめ書きは品質にも効く。
2. **書き手を増やす。** 1人で全区の土地勘を持つのは無理がある。区ごとに担当を分ける。
3. **検索需要の高い駅から書く。** 全駅公開を待たず、書けた駅から公開する。データ構造は既にそれを許している（コンテンツの無い駅はページを生成しない）。
4. **AI に下書きさせない。** 事実の整理はAIでよいが、「実際に住むならどうか」の一文は人間が書く。ここを妥協すると全体が凡庸になる。

| 論点 | 内容 | 決める時期 |

| 多言語の範囲 | 443駅 × 13言語 = 5,759ページぶんの散文。全言語で全駅やるのか、言語ごとに駅を絞るのか | 多言語展開前 |

## 5. 所要時間の計算について

L2 で全443駅の所要時間を計算した。方法と精度は [10-commute-estimation.md](./10-commute-estimation.md)。

これは**時刻表に基づく値ではなく推定値**である。既知の18区間との比較で平均 +0.8分、17/18 が誤差±3分以内に収まっているので、「30分以内」といった絞り込みには使える。

将来的に経路検索の商用APIやGTFSに置き換える余地はあるが、**443駅 × 7オフィス街 = 3,101件の経路をAPIで引くとコストが読めない**ため、当面はこの計算値で進める。置き換えるとしても、この計算値が精度の下限を保証する。
