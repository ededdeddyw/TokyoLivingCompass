# 要件定義 / MVP スコープ

構想の全体像は [00-concept.md](./00-concept.md) を参照。本書はそれを「実装できる単位」に落としたもの。

---

## 1. プロダクトの一行定義

> 勤務先・予算・ライフスタイルを入力すると、東京のどの駅に住むべきかを根拠つきで返すサービス。

「物件を探す前に、どこに住むかを決める」ためのプロダクトであり、物件検索そのものは行わない（不動産ポータルへ送客する）。

---

## 2. ペルソナ

| # | ペルソナ | 状況 | 主な judgment 基準 |
|---|---|---|---|
| P1 | 来日予定の外国人single | 11月に来日、虎ノ門勤務、家賃17万まで | 通勤 / 静かさ / 外国人生活適性 / 英語対応 |
| P2 | 東京在住の外国人（引越し検討） | 現在は港区、家賃を下げたい | 家賃コスパ / 通勤 / 飲食店 |
| P3 | 日本人の単身社会人 | 転職に伴う引越し、都心通勤 | 家賃コスパ / 通勤 / 飲食店 / 街の雰囲気 |
| P4 | 日本人ファミリー | 子どもの就学、2LDK 以上 | 治安 / 静かさ / 公園 / ファミリー適性 |
| P5 | B2B（Relocation 会社） | 赴任者の住居候補を提示したい | データの網羅性 / API |

MVP は **P1 と P3** を主軸に設計する（外国人と日本人の両方を最初から検証するため）。

---

## 3. MVP スコープ

### 3.1 やること

| ID | 機能 | 内容 | 優先度 |
|---|---|---|---|
| F1 | 駅ページ | 1駅 = 1ページ。スコア・家賃・通勤・生活情報・在住者コメント | 必須 |
| F2 | 駅一覧 / 絞り込み | 全対象駅の一覧、家賃・スコアでの絞り込みと並び替え | 必須 |
| F3 | 駅スコア | 16軸の 0–100 スコアと ◎○△× 表示 | 必須 |
| F4 | 駅比較 | 任意の2駅を並べて比較（`/compare/a-vs-b`） | 必須 |
| F5 | 勤務先起点の逆引き | 勤務地・家賃上限・間取り・所要時間から候補駅をランキング | 必須 |
| F6 | パーソナライズ重み付け | ユーザーが軸の重みを変えるとランキングが変わる | 必須 |
| F7 | 多言語対応 | URL 構造・データ構造として最初から対応。初期は ja / en を実運用 | 必須 |
| F8 | AI 駅診断（対話型） | 自然文の相談 → 候補駅の提示 | 後続 |
| F9 | 生活費シミュレーション | 家賃以外を含む総生活費の試算 | 後続 |
| F10 | 不動産送客 | 各駅ページから提携先へのリンク | 後続 |

### 3.2 やらないこと（MVP 時点）

- 物件そのものの検索・掲載
- ユーザー登録 / ログイン
- ユーザー投稿レビュー（初期の主観は編集側が担保する）
- 地図上でのインタラクティブ検索
- 課金機能

### 3.3 初期対象駅

構想 §18 に従い **50駅** を目標とし、内訳は「外国人認知度の高い有名駅 20 / 日本人には知られている穴場住宅地 30」。

現時点でリポジトリに投入済みのシードは 12 駅（[data/stations](../data/stations)）。まず 12 駅で全機能を通し、そのあと 50 駅まで水平展開する。

## 4. 機能要件

### F1. 駅ページ

URL: `/{locale}/stations/{slug}`

必須表示項目（構想 §5 の表に対応）:

- 総合評価（デフォルト重みでの 0–10 換算）
- 家賃相場（1R / 1K / 1LDK / 2LDK）
- 都心アクセス（新宿・渋谷・東京・品川・大手町・虎ノ門・六本木への所要時間と乗換回数）
- 路線 / 始発の有無 / 朝の混雑度
- 16軸スコア（◎○△× と数値の併記）
- 周辺施設（スーパー、商業施設など）
- 似ている駅 / 向いている人 / 向かない人
- 東京在住者コメント（人間が書く。AI 生成しない）

### F3. 駅スコア

- 全軸 0–100 の整数。定義と付け方は [03-scoring.md](./03-scoring.md)。
- 表示は ◎○△× に丸めるが、内部は数値で保持し、ランキング計算に使う。

### F5. 勤務先起点の逆引き

入力:

| 項目 | 型 | 必須 |
|---|---|---|
| 勤務先駅 | 主要オフィス駅から選択 | 必須 |
| 家賃上限 | 円 | 必須 |
| 間取り | 1R / 1K / 1LDK / 2LDK | 必須 |
| 通勤時間上限 | 分 | 任意（既定 40分） |
| 乗換回数上限 | 回 | 任意（既定 1回） |
| 重視する軸 | 複数選択 | 任意 |

出力: 適合度（%）つきの駅ランキング。各駅について「なぜ推すのか / 弱点 / 似た候補」を必ず添える（構想 §7）。

### F6. パーソナライズ重み付け

- 重みプリセット（単身 / ファミリー / 静かさ重視 / コスパ重視 / 外国人向け）を用意。
- 重みは URL クエリに載せ、共有・SEO・再現性を確保する。

---

## 5. 非機能要件

| 区分 | 要件 |
|---|---|
| SEO | 駅ページ・比較ページは静的生成。`hreflang`、構造化データ、sitemap を出力 |
| パフォーマンス | LCP < 2.5s（モバイル 4G 想定）。駅ページは JS 非依存で内容が読める |
| 多言語 | 全ページが locale prefix つき URL を持つ。翻訳欠落時は日本語にフォールバックせず「未翻訳」として扱う |
| アクセシビリティ | ◎○△× は色だけでなく記号とテキストで判別可能にする |
| データ整合性 | ビルド前に全駅データをスキーマ検証し、不正なら fail させる |
| 拡張性 | 数万ページ規模を想定。データは DB へ移行できる形で構造化しておく |

---

## 6. データの信頼性についての注意（重要）

現在リポジトリに入っている駅データは **開発用のシード値であり、実測・出典に基づく確定値ではない**。

- 家賃相場・所要時間・スコアはいずれも暫定値で、公開前に出典つきの値へ差し替える必要がある。
- 各駅データは `dataQuality` フィールドで状態を持つ（`seed` / `reviewed` / `verified`）。
- `seed` のデータを本番公開してはならない。検証フローは [06-roadmap.md](./06-roadmap.md) の Phase 2 に定義する。
