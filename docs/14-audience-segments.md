# 読み手の区分

458駅を1つの総合点で並べない。**誰にとっての住みやすさなのかを先に決めてから、
その区分の中でだけ比べる。**

---

## 1. なぜ区分するのか

高円寺のファミリー適性が、全458駅中94パーセンタイルに出ていた。
内訳はこうだった。

| 材料 | 高円寺の値 | 順位 | 重み | 寄与 |
|---|---|---|---|---|
| 公園（半径1,200m） | 38か所 | 83% | 0.30 | 24.9 |
| クリニック＋薬局（800m） | 48軒 | 94% | 0.20 | 18.8 |
| スーパー（800m） | 15軒 | 93% | 0.20 | 18.6 |
| 平坦さ | flat | — | — | 15.0 |
| 駅前の酒場の少なさ（300m） | 63軒 | 96% | 0.15 | 0.6 |

**この77.9点の中に、子どもに関する数字は1つも入っていなかった。**
保育園も、小学校も、児童館も、子育て世帯の比率も、データとして持っていなかった。
「クリニック」はクリニックと薬局の数で、小児科があるかどうかは分からない。
[03-scoring.md](./03-scoring.md) §2 は `family` を「学校、公園、小児科、
ベビーカー移動のしやすさ」と書いていたが、実装には学校も小児科も入っていなかった。

そして駅から300m以内に酒場が63軒あるという事実は、重みが0.15しかないため
**0.6点しか引いていなかった。**測り方の問題ではなく、
「公園・医療・スーパーが多くて平坦」を「子育てしやすい」と名付けていたことが問題である。

同じ点数帯に、実態が正反対の駅が並ぶ。武蔵小山は83.3点で高円寺より高いが、
こちらは酒場の少なさで11.4点を得ている。1つの物差しで並べる限り、この2駅は区別できない。

---

## 2. 3つの軸

それぞれ2つに分かれ、組み合わせて8区分になる。

| 軸 | 分かれ目 | この軸で重みが変わるもの |
|---|---|---|
| **世帯** | 子どもがいる / いない | 学校・保育園・公園・平坦さ ↔ 外食・終電・職場への近さ |
| **夜の過ごし方** | 街で過ごす / 家で過ごす | 深夜まで営業している店の多さ ↔ 人の音と車の音の少なさ |
| **お金の置き方** | 家賃を抑える / 立地に出す | 家賃コスパ ↔ 都心アクセスと街並み |

区分ごとに実際どの駅が上に出るかは §3.1 の表にある。

**3つめの軸は、まだ確定していない。**「通勤の形（毎日同じ都心へ通う / 行き先が変わる）」
「身近で済ませるか（駅前で終わらせたい / 電車で出てもいい）」も候補に残っている。
当面は「お金の置き方」で進め、駅ページを何十枚か作ったところで見直す。

## 3. 18軸との関係

**18の評価軸は事実のまま動かさない。**区分は、どの軸を見るかを決めるだけである。
[03-scoring.md](./03-scoring.md) §5 の重みプリセットを、この3軸から組み立てる形に置き換えた。

以前のプリセットは `single` / `family` / `quiet` / `value` / `international` の5つで、
互いに重なっていた。「単身で、かつ静かな街に住みたい」人がどれを選べばいいか決まらない。
3つの軸に直すと、その穴が埋まる。

画面では8つの長い名前を並べる代わりに、3つの軸をそれぞれ2択で出し、
押すとその軸だけが入れ替わる（`src/components/SegmentPicker.tsx`）。
URLに区分のキーを載せるので、選んだ状態のまま人に渡せる。

---

## 3.1 重みを変えるだけでは並び順が直らなかった

最初の実装は、18軸すべてを重み1から始め、区分が選んだ軸に足す形だった。
これでは**どの区分でも池袋と御茶ノ水が上位に出た。**原因は2つあった。

**1. 重みつき平均は、多くの軸で平均より上の駅を上に出す。**
御茶ノ水は通勤・乗換・医療・買い物・飲食店がどれも高い。
「夜は家で過ごす」を選んで静かさの重みを上げても、静かさ1軸の低さが
ほかの軸の高さに埋もれる。渋谷も同じで、静かさが29点しかなくても、
通勤・乗換・買い物・医療がどれも95点を超えるため1位に出ていた。

**2.「家賃を抑える」に使える軸がなかった。**
`rentValue` は家賃コスパ、つまり同じ利便性の駅と比べた安さである。
池袋の `rentValue` は100で、ワンルーム8万9千円に対して通勤の利便性が
きわめて高いためそうなる。コスパとしては正しいが、
**家賃を抑えたい読み手が求めているのは絶対額の安さ**であって、コスパではない。

次の3つで直した。

1. **絶対額の安さを表す軸 `rentLow` を足した。**家賃の帯から出した指数の、
   駅どうしの相対的な位置を反転させる。443駅ぶんある。
   池袋の `rentLow` は50、舎人100、竹ノ塚99、神谷町0、六本木一丁目0である。
2. **区分を「全軸の重みづけ」ではなく「見る軸の選択」に変えた。**
   誰にとっても向きが同じ6軸だけを低い重みで残し、
   残りは選んだ側が足したときだけ点数に入るようにした（[03-scoring.md](./03-scoring.md) §5）。
3. **区分が重く見る軸に足切りをかけた。**
   静かさを選んだ読み手に、静かさが下位3割に入る駅を上位で見せない。
   足切りに引っかかった駅は一覧の後ろへ回す（`scoring.ts` の `rankBySegment()`）。
   境目は軸ごとに駅の分布から出す。絶対値で「40点未満」と決めると、
   同じ40点が静かさでは下位1割、家賃の安さでは下位4割にあたるためである。

| 選択 | 足切りに使う軸 |
|---|---|
| 子どもと住む | ファミリー適性 |
| 子どもなし | 一人暮らし適性 |
| 夜は街で過ごす | ナイトライフ |
| 夜は家で過ごす | 静かさ |
| 家賃を抑える | 家賃の安さ |
| 立地に出す | 都心アクセス |

落とす割合は2割では足りなかった。静かさの下位2割は40点以下で、
東京駅の41点が残っていた。「夜は家で過ごす」の上位に東京駅を出す一覧は、
読み手の役に立たない。3割にすると東京駅も渋谷も外れる。

直したあとの区分ごとの筆頭はこうなった。

| 区分 | 上位5駅 |
|---|---|
| 子どもと住む・夜は街で・家賃を抑える | 中野、南阿佐ケ谷、新高円寺、阿佐ケ谷、池袋 |
| 子どもと住む・夜は街で・立地に出す | 御茶ノ水、秋葉原、御徒町、池袋、上野 |
| 子どもと住む・夜は家で・家賃を抑える | 北池袋、荒川二丁目、田端、豊島園、荒川区役所前 |
| 子どもと住む・夜は家で・立地に出す | 茗荷谷、北池袋、田端、戸越公園、旗の台 |
| 子どもなし・夜は街で・家賃を抑える | 池袋、阿佐ケ谷、高円寺、中野、荻窪 |
| 子どもなし・夜は街で・立地に出す | 渋谷、永田町、新橋、神田、秋葉原 |
| 子どもなし・夜は家で・家賃を抑える | 茗荷谷、東中野、南阿佐ケ谷、田端、千駄木 |
| 子どもなし・夜は家で・立地に出す | 中目黒、清澄白河、茗荷谷、大井町、武蔵小山 |

**まだ気になる点が残っている。**「子どもと住む・夜は街で・立地に出す」の上位に
秋葉原と御徒町が並ぶ。この2駅の `family` は52点・50点で、足切りを通る。
台東区は OpenStreetMap の登録が23区で最も細かく、学校も園も公園も多く数えられる
（[03-scoring.md](./03-scoring.md) §4.4）。区ごとの登録率を確かめるまで、
この2駅の順位は保留して読む。

## 4. 「子どもがいる」を本物にするために要るデータ

いまの `family` は、子どもに関する数字を1つも持っていない。次の順で埋める。

| データ | 出典 | 状態 |
|---|---|---|
| 小学校・中学校の位置 | OpenStreetMap `amenity=school` | 11,709件を取得し、スコアに入れた |
| 幼稚園・保育園の位置 | OpenStreetMap `amenity=kindergarten` / `childcare` | 幼稚園5,154件・保育園882件を取得し、スコアに入れた |
| 保育園の定員 | 各区が公開している施設一覧 | 未着手。23区で様式が違う |
| 待機児童数 | 東京都福祉局が区ごとに公表 | 未着手 |
| 子育て世帯の比率 | 国勢調査 町丁・字等別集計（e-Stat） | 未着手 |

学校と園を入れ、繁華街・大きな駅であるぶんを掛け算で割り引くようにした結果、
高円寺は94点から47点（243位）になり、「子育てしやすい」タグは外れた。
タグが付くのは71駅で、上位は西巣鴨・新庚申塚・戸越公園・千石・庚申塚である。
配分は [03-scoring.md](./03-scoring.md) §4.3 にある。

**残りが揃うまで、定員や待機児童数には触れない。**根拠のない評価語を出すほうが、
書かないより悪い（[13-japanese-style-rules.md](./13-japanese-style-rules.md) ルール19）。

OpenStreetMap の登録の細かさが区によって20倍違う問題は、学校の数にも同じように表れる
（[03-scoring.md](./03-scoring.md) §4.4）。学校は公共施設なので店ほど偏らないはずだが、
数を使う前に区ごとの登録率を確かめる。
