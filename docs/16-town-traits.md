# 街の特色の集め方

駅ページには、地図・統計・ハザードマップのような数えられる情報しか入っていなかった。
「中目黒といえば目黒川」「大崎は休日に人が減る」のような街の特色は、どのデータにも無い。
この文書には、街の特色をどこから取り、どう書くかを決めたことと、残っている作業をまとめる。

---

## 1. 決めたこと

| 決めたこと | 理由 |
|---|---|
| 特色は1駅5個ほど。出典の文を写さず、読み取った内容をまとめ直して書く | 出典の表現を使うと著作権の問題になる。事実そのものには著作権が無い |
| 出典からは特色だけを取り、家賃・所要時間・店の数のような数字は取らない | 数字は既存の出典（`data/computed/`）を正とする。まとめ記事の数字は誤っていることがある |
| 1つの特色ごとに、どの記事から読み取ったかを記録する | 読み手が確かめられるようにする。Wikipedia は CC BY-SA なので出典の表示が要る |
| 日本語表現ルール（`CLAUDE.md`）をそのまま適用する | 画面に出す文章なので、ですます調・1文60字以内・比喩を使わない |
| 災害や治安にかかわる特色は、事実だけを書き、評価を加えない | ルール32 |

## 2. 出典ごとの扱い

| 出典 | 使うか | 理由 |
|---|---|---|
| Wikipedia 日本語版（駅の記事・町の記事） | 使う。全駅の下地にする | CC BY-SA 4.0。API（api.php）はこの環境から続けて呼ぶと 429 を返し続けたため、記事の原文を返す `?action=raw` を、間隔を空けて取っている |
| 三井のリハウス「ぶらリハウス」 | **次に使う**（§4） | 運営会社の利用条件に、機械での取得を禁じる条項は無い。robots.txt も記事を禁止していない。ただし「権利者の許可なく複製、転用などされることのないよう」とあるので、本文を写さず、言い換えた流用もしない |
| アットホーム「タウンライブラリー」 | 使わない | 利用規約 第4条第13号が、クローラーでの取得を禁じている。第11号は、許諾のない商業目的での利用を禁じている。許諾が取れれば使える |

利用条件の確認日はどれも 2026-10-06。

- アットホーム利用規約: https://www.athome.co.jp/help/kiyaku.html
- 三井不動産リアルティ「サイトご利用上の注意」: https://www.mf-realty.jp/attention/

## 3. Wikipedia から作る手順

1. `python3 scripts/fetch-wikipedia-towns.py` で、駅の記事と町の記事を `.cache/wikipedia/` に取る。
   読むのは「駅周辺」「概要」「地理」「地域」などの節だけで、のりば・年表・利用状況は読まない。
2. 記事を読み、特色を5個ほどにまとめ直す。各特色に、読み取った記事の名前（`from`）を付ける。
3. **特色を1つずつ記事と突き合わせる（裏取り）。** 記事に無い要素は削り、削ると意味が通らなければ特色ごと消す。
4. `python3 scripts/merge-town-traits.py 駅ごとのファイル…` で `data/town-traits/wikipedia.json` にまとめる。
   `from` が出典に無い記事名を指していないか、1文が60字を超えていないか、数字を含んでいないかをここで止める。

### 結果（2026-10-06）

- 458駅のうち432駅に特色がある。特色は合計1,762個。
- 1駅あたりの数: 5個が194駅、4個が133駅、3個が67駅、2個以下が38駅、0個が26駅。
- 0個の駅は、記事が駅の所在地と構造だけのもの（都電荒川線の停留場、水道橋、大門など）。

### 裏取りで見つかったこと

**まとめる段階で、記事に無い知識が混ざる。** 1回目にまとめた1,764個のうち、
裏取りで約270個を直し、1個を消した。混ざったものは次のとおりである。

| 何が混ざっていたか | 例 |
|---|---|
| 別の駅の記事に書かれていた内容 | 武蔵小山の「都内で最も長いアーケード」（西小山の町の記事の内容） |
| 書き手の知識で足した説明 | 「旧東京工業大学」「コスプレの撮影場所」「貨物輸送を取り次ぐフォワーダー」 |
| 記事より強い言い方 | 「大きな」「多く集まっています」「大企業の」 |
| 2つの記事の内容を1文に混ぜたもの | `from` と中身の記事が食い違う |

裏取りは省かない。まとめた人と別の人（別のエージェント）が、記事の本文だけを見て確かめる。

### 記事の取り違え

- 町の記事として、神社・公園・大学の記事が当たる駅がある（穴守稲荷神社、飛鳥山公園、駒澤大学など）。
  施設が駅の近くにあることだけを使う。
- 都立大学駅の「東京都立大学」、荏原町駅の「荏原区」は外した。大学はもうその場所に無く、荏原区は範囲が広すぎる。
- 栄町（都電荒川線）に千葉県栄町の記事が当たっていた。冒頭に他県の名前がある記事は外すようにした。

### Wikipedia で分かったこと

- 歴史や文化のある街（神楽坂、高円寺、北千住、清澄白河、人形町）は記事が厚く、その街ならではの特色がよく出る。
- 駅の記事が施設の一覧だけの駅は、地名の由来や近くの施設の話が中心になり、「住むとどうか」はほとんど読み取れない。
- 「休日は静か」「JRに強い」のような、住んでいる人の目線の話は、Wikipedia にはほとんど書かれていない。

## 4. ぶらリハウスを足す（次の作業）

Wikipedia で足りない「住んでいる人の目線」を、ぶらリハウスで補う。

- 一覧ページ: https://www.rehouse.co.jp/relifemode/tag/tokyo/ （東京23区で約112件。湾岸タイムズと沿線レポートを除くと、駅や街の記事は約80〜85件）
- 記事の例: https://www.rehouse.co.jp/relifemode/burarehouse/akasakamitsuke/
- 全458駅には届かない。記事のある駅だけ、Wikipedia の特色に足す。
- 記事の形式は揃っていない（【駅名】形式の記事と、別の形式の記事が混ざっている）。
  一部の記事は `/relifemode/column/at/` の下にある可能性がある。
- 本文を写さず、読み取った内容をまとめ直す。言い換えた流用もしない。
  出典として記事へのリンクと確認日を残す。
- 取得の間隔を空け、robots.txt に従う。
