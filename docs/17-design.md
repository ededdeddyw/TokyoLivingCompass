# 画面の見た目の決まりごと

駅ページは、文章の深さでは既存のまとめ記事に勝てるようになってきたが、見た目は
文字が続くだけで、どこに何があるかが分かりにくかった。2026-10 に見た目を作り直した。
この文書には、そのとき決めた色・部品・並べ方と、その理由をまとめる。

---

## 1. サイトに持たせる印象と色

| 持たせたい印象 | 理由 |
|---|---|
| 正直で、事実に基づく | 都合の悪い事実も書き、出典を示すサイトなので、信頼が何より大切 |
| 明るく、前向き | 住む街を選ぶのは新しい暮らしを始める場面。不動産屋の重さより街歩きの軽さを出す |
| 迷わせない | 名前のとおり方角を示す。色で判断の手がかりを出すが、色に頼りすぎない |

ここから次の色を選んだ（`src/app/globals.css` の `@theme`）。

| 役割 | 色 | 使う場所 |
|---|---|---|
| 主役 | 水色〜青緑（`accent` `accent-strong` `accent-bright`） | 見出しの帯、リンク、選んでいる状態、アイコン |
| 差し色 | あたたかいオレンジ（`sun`） | 強みの印、「どんな街か」、一言の左の線、総合評価のカード。画面の1割以下に抑える |
| 点数のよい側 | 深い青緑（`good`） | ◎・強み・向いている人 |
| 点数の悪い側 | コーラル（`bad`） | ×・弱み・向かない人 |

差し色のオレンジと点数の悪い側の色を分けたのは、オレンジが「警告」と読まれないようにするためである。
点数の良し悪しは、色だけでなく ◎○△× の記号とアイコンも必ず添える。赤と緑を見分けにくい人がいる。

飲食店・カフェ・ナイトライフは、多いほうがよいかどうかが人によって違う（`CLAUDE.md` ルール40）。
良し悪しの色を付けず、中立の色の棒で出し、強み・弱みの一覧にも入れない（`PREFERENCE_AXES`）。

## 2. 駅ページの並べ方

参考にしたのは、点数に一言の言葉を添える Walk Score と、最上部に分野ごとの成績を並べる
Niche・AreaVibes（英語圏の街の評価サイト）である。**一番上の画面で、この駅の強みと弱みが分かる**ようにし、
詳しい本文は下で読む作りにした。

1. 駅名の帯（区・路線・一言・性格タグ）
2. 要点のカード（家賃の目安・いちばん近いオフィス街・使える路線・総合評価）
3. 目次（画面の上に固定。スマホでは横にスクロールする）
4. 要約の本文
5. どんな街か
6. 家賃（帯と平均を1枚のカードに。以前は同じ出典の数字を2つの節に出していた）
7. 通勤（短い順の横棒。乗り換えの有無をアイコンで）
8. 評価（強み3つ・弱み3つを先に。18軸は畳んで「すべて見る」）
9. 向いている人・向かない人
10. 住むと分かること（アイコン付きのカード。一言を見せ、長い本文は「続きを読む」で畳む）
11. 比べる（近くの駅・迷いやすい駅）

本文を畳んでも HTML には残るので、検索にも読み上げにも届く。
