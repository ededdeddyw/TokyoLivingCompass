# スコア設計

構想 §6「東京の駅偏差値」の実装仕様。

---

## 1. 原則

- 全軸 **0–100 の整数**。50 が「東京の住宅地として平均的」。
- 画面には **5点満点**で出す。0点を1.0、50点を3.0、100点を5.0に置き、0.5刻みに丸める
  （`toFivePoint`）。20で割ると平均の駅が2.5点になり、読み手が平均を下と受け取るため。
- 単一の総合ランキングは作らない。**重みはユーザー側が決める**（構想 §6）。
- 表示は ◎○△× に丸めるが、内部は数値で保持する。
- スコアは「東京の住宅地の中での相対評価」であり、全国比較ではない。

## 4. スコアの付け方

現行のシードデータは編集者の判断による暫定値。公開版では以下の混成とする。

14軸を `scripts/build-scores.py` が全458駅ぶん計算している（`safety` だけは、
駅から800m以内に町丁がない羽田空港第3ターミナルを除く457駅）。
家賃から出す2軸（`rentValue` と `rentLow`）は、家賃相場が揃った443駅ぶんある。
残る2軸は、人の判断が要るため、まだ入っていない。

| 軸 | 何から出しているか | 状態 |
|---|---|---|
| `commute` | 7つのオフィス駅への所要時間の平均 | 計算済み 458駅 |
| `transitConvenience` | 路線数と事業者の数 | 計算済み 458駅 |
| `shopping` | 徒歩圏のスーパーの数と価格帯の幅 | 計算済み 458駅 |
| `food` `cafe` `nightlife` `fitness` | 徒歩圏の飲食店・カフェ・酒場・ジムの数 | 計算済み 458駅 |
| `healthcare` | 徒歩圏のクリニック・薬局と、総合病院までの距離 | 計算済み 458駅 |
| `nature` | 徒歩圏の公園の数 | 計算済み 458駅 |
| `quietness` | 人の音（駅から300m以内の酒場と飲食店の数と、用途地域の容積率）と、車の音（幹線道路・高速道路までの距離と種別） | 計算済み 458駅 |
| `family` | 学校・園・公園・スーパーが歩ける範囲に足りているかと坂の少なさを出したうえで、繁華街であるぶんを割り引く | 計算済み 458駅 |
| `singleLife` | 飲食店・カフェ・スーパーの多さと、通勤の速さ | 計算済み 458駅 |
| `disaster` | 浸水想定区域に入る地点の割合と、想定される深さ | 計算済み 458駅 |
| `rentValue` | 通勤スコアから予想される家賃と、実際の家賃の差 | 計算済み 443駅 |
| `rentLow` | 家賃の帯から出した指数の、駅どうしの相対的な位置（向きを反転） | 計算済み 443駅 |
| `safety` | 警視庁の町丁別認知件数。粗暴犯を主に見る | 計算済み 457駅 |
| `internationalFriendliness` | 区別の外国人人口比率（未取得） | **未着手** |
| `style` | 機械で出せる材料がない | **人が判断する** |

つまり「機械で出せる軸は機械で出し、土地勘が要る軸に人間を集中させる」。これが構想 §4.2 の差別化を運用可能にする形。

いくつか注意点がある。

- `quietness` は、人の音と車の音の両方から出す。人の音は駅から300m以内の酒場と
  飲食店の数、車の音は幹線道路・高速道路までの距離と種別（`data/computed/roads.json`）で見る。
  店の数だけで人の音を測ると、大きな駅を拾えない。東京駅は300m以内の酒場が1軒しか
  登録されておらず、静かさが76点に出ていた。1日79万人が乗り降りする駅の駅前は静かではない。
  そこで店の多さと、用途地域の容積率から出した「高い建物が建ち並ぶ街である度合い」の、
  高いほうを人の音として使う（`built_density()`）。上位3割に入る駅だけが減点されるよう、
  70パーセンタイルを起点に引き直している。東京駅は39点、池袋は41点になり、
  駅から300m以内に酒場が1軒も無い西巣鴨は65点のまま残る。
  以前はここに1日の乗降客数を使っていたが、乗降客数は駅を通り抜ける人の数であって、
  駅前がどういう街かを表さない（§4.5）。
  鉄道の音は、地上か高架か地下かのデータを持っていないため入っていない。
  繁華街から離れていることは静かであることを意味しない。岩本町は駅から300m以内の
  酒場が35軒と神田の83軒より少ないが、昭和通りと首都高速1号上野線の高架が、
  どちらも駅のすぐそばを通る。
  人の声は少なくても車の音は一日中続く（[13-japanese-style-rules.md](./13-japanese-style-rules.md) ルール41）。
- `quietness` だけは半径300mで数える。ほかの軸は「歩いて行ける選択肢の多さ」なので
  800m圏でよいが、静かさは「駅を出たところがどうか」だからである。
  800m圏だと、都心では隣の駅と圏が重なって差が消える。淡路町と神田は800m圏のPOIの
  54%が同じもので、酒場の数は淡路町298軒・神田211軒と、実際とは逆に出ていた。
  300m圏で数え直すと淡路町41軒・神田83軒になり、街を歩いた感覚と向きがそろう。
- `rentValue` は家賃の安さそのものではない。通勤スコアから予想される家賃と実際の家賃の差なので、
  「都心に近いのに安い駅」が上位に来る。郊外の駅が家賃の安さだけで上位を占めることはない。
- `rentLow` は絶対額の安さである。`rentValue` とは別の軸として持つ。
  池袋の `rentValue` は100だが、ワンルームの相場は8万9千円で、`rentLow` は50しかない。
  通勤の利便性がきわめて高いためコスパでは最上位に出るが、
  家賃を抑えたい読み手が見たいのは絶対額であって、コスパではない
  （[14-audience-segments.md](./14-audience-segments.md) §3.1）。
- `disaster` は想定最大規模の試算に対する点であり、ふだん浸水するかどうかではない
  （[13-japanese-style-rules.md](./13-japanese-style-rules.md) ルール32）。

残る3軸をどう埋めるかは [11-all-stations-plan.md](./11-all-stations-plan.md)。

スコアは**軸ごとに任意**である。458駅ぶんが一度に揃うことはなく、計算できる軸・購入した軸・
人が判断した軸が順に埋まっていくため。総合評価は**入っている軸だけで重みを正規化し直す**ので、
半分しか埋まっていない駅が不当に低く出ることはない。

計算値と人の入力が両方ある場合は**人の入力を優先**する。

> 注意: `dataQuality: "seed"` の駅のスコアは推定値であり、一次データには紐づいていない。

### 4.3 ファミリー適性の中身

以前は公園・クリニック・スーパー・平坦さだけで出していた。子どもに関する数字が
1つも入っていなかったため、駅から300m以内に酒場が63軒ある高円寺が、
全458駅の94パーセンタイルに出ていた（[14-audience-segments.md](./14-audience-segments.md) §1）。

学校・幼稚園・保育園を取得し、次の配分で組み直した。
施設の多さを出したうえで、繁華街・大きな駅であるぶんを割り引く形にしている。

| 材料 | 半径 | 重み |
|---|---|---|
| 小中学校の数 | 1,500m（歩いて通う距離） | 0.26 |
| 幼稚園と保育園の数 | 1,000m（送り迎えの距離） | 0.26 |
| 公園の数 | 1,200m | 0.22 |
| スーパーの数 | 800m | 0.13 |
| 平坦さ | — | 13点満点 |

この4つと平坦さを足した値に、`1 - 0.55 × 繁華街の度合い` を掛ける。
繁華街の度合いは、駅から300m以内の酒場の多さと、1日の乗降客数から出した
「大きな駅である度合い」（`hub_size()`）の、高いほうを使う。

引き算ではなく掛け算にした理由がある。酒場の多さを引き算で減点すると、
施設の数が多い駅では引ききれない。池袋は駅から1,500m以内に小中学校が34校あるため、
引き算では上位に残ってしまう。1日193万人が乗り降りする駅は、学校が34校あっても
子どもと暮らす場所としては落ち着いた環境ではない。

酒場の数だけで繁華街かどうかを判定できない点にも手当てが要る。
OpenStreetMap に登録されている池袋の酒場は、駅から800m以内で53軒しかない。
御徒町の728軒、淡路町の298軒と比べて桁が違い、実態と合わない（§4.4）。
半径を変えても直らないため、乗降客数を併せて見ている。

組み直した結果、高円寺は94点から47点（243位）になった。
上位は西巣鴨100点、新庚申塚100点、戸越公園99点、千石99点、庚申塚99点である。
下位は桜田門0点、虎ノ門0点、青海1点、霞ケ関1点で、オフィス街と埋立地が並ぶ。

**まだ入っていないもの。**保育園の定員と待機児童数、小学校の学区、小児科の有無。
どれも区ごとに様式が違うので、[14-audience-segments.md](./14-audience-segments.md) §4 の順で埋める。

### 4.4 OpenStreetMap の登録の細かさが、区によって大きく違う

`food` / `nightlife` / `cafe` / `shopping` の4軸は、OpenStreetMap に登録された店の数から
計算している。この数は、区によって登録の細かさが大きく違う。
駅から500m以内にある商業の建物の棟数を数えると、中央値で台東区205棟・練馬区75棟に対して、
板橋区9棟・大田区14棟・目黒区14棟だった。**20倍以上の開きがある。**

区ごとの `food` スコアの中央値も、台東区93・千代田区92に対して、
足立区16・江東区19・大田区21・板橋区21と大きく開く。
都心に店が多いのは事実だが、**この開きの一部は地図を作った人の多さの差である。**

はっきり分かっている例として、武蔵小山は300m以内の飲食店が19軒しか登録されていない。
武蔵小山商店街パルムは全長約800mのアーケード商店街で、この数は実態と合わない。

分かっている対応は次の2つである。

1. **繁華性の判定には絶対数を使わない。**まわりの駅との倍率で測る
   （[12-quality-standard.md](./12-quality-standard.md) §3.1.1.2）。
2. **本文で「店が少ない」と書く前に、その駅の登録の細かさを疑う。**
   同じ区の他の駅と比べて、そこだけ少ないのかを確かめる。

#### ファミリー適性は、駅の大きさで割り引く

酒場の数だけで繁華街らしさを引くと、池袋のような大きな駅を拾えない。
OpenStreetMap に登録されている池袋の酒場は、駅から800m以内で53軒である。
御徒町の728軒、淡路町の298軒と比べて桁が違い、実態と合わない。半径を変えても直らない。

そこで**乗降客数も見る**。1日193万人が使う駅は、酒場の登録が少なくても、
子どもと暮らす場所としては落ち着いた環境ではない。
酒場の多さと駅の大きさの、高いほうを使って割り引く。

```
施設 = 学校0.26 + 幼稚園と保育園0.26 + 公園0.22 + スーパー0.13 + 平坦さ13点
繁華度 = max(300m以内の酒場の順位, 乗降客数の順位) ÷ 100
ファミリー適性 = 施設 × (1 - 0.55 × 繁華度)
```

引き算ではなく掛け算にしたのは、池袋のように施設が多い駅では引ききれないためである。
池袋は小中学校が34校あるが、1日193万人が使う駅である。

組み直した結果は、西巣鴨95・中延87・武蔵小山85・板橋83に対して、
池袋53・渋谷30・新宿5である。高円寺は56で、施設は揃っているが
繁華街であるぶんが引かれている。

#### 乗降客数を、もう1つの物差しとして持つ

OpenStreetMap だけで街の規模を測ると、地図を作った人の多さに引きずられる。
そこで、**国土数値情報「駅別乗降客数データ」**（S12-22、国土交通省）を取り込んだ。
鉄道事業者が報告した数を国が集計したもので、全国で同じ基準である。

`python3 scripts/fetch-passengers.py` → `data/computed/passengers.json`。
458駅のうち457駅に、1日あたりの乗降客数（2021年度）が入る。
とうきょうスカイツリー駅だけは、出典側の値が0なので入っていない。

上位は新宿220万人、池袋193万人、渋谷170万人、北千住97万人、東京79万人である。
御徒町は9.9万人で76位、湯島は2.8万人で220位、末広町は1.7万人で304位だった。
店の数で並べたときに上位に来ていた湯島・末広町が、ここでは下がる。

**この数を店の数の代わりにはしない。**乗降客数は、働きに来る人も乗り換えるだけの人も
同じ1人として数えるため、東京駅が5位、高田馬場が6位に来る。
街の規模を測る物差しとして、店の数と並べて使う。

#### 朝の混雑率を路線ごとに持つ

「東西線は朝が混む」と書いても、どれくらい混むのかが読み手に伝わらない。
国土交通省が毎年度公表している「都市鉄道の混雑率調査結果」から、
路線ごとの最混雑区間と混雑率を取り込んだ。

`python3 scripts/fetch-congestion.py` → `data/computed/congestion.json`。
62路線のうち47路線に、令和7（2025）年度の値が入る。

| 路線 | 混雑率 | 区間 | 時間帯 |
|---|---|---|---|
| JR埼京線 | 167% | 板橋→池袋 | 7:51〜8:51 |
| 東京メトロ日比谷線 | 163% | 三ノ輪→入谷 | 7:50〜8:50 |
| 東京メトロ東西線 | 160% | 木場→門前仲町 | 7:50〜8:50 |
| JR総武本線 | 160% | 新小岩→錦糸町 | 7:31〜8:31 |

混雑率の目安は、資料1に載っている国土交通省の記述による。
100%は座席につくか吊革や柱につかまることができる状態、150%は肩が触れ合わない程度で
ドア付近の人が多くなる状態、180%は肩が触れ合ってやや圧迫感があり体の向きを
変えるのが難しい状態、200%は体が触れ合って相当な圧迫感があり
ドア付近の人は身動きがとれない状態である。

駅ページには、その駅の値が超えている段の説明だけを添える。167%の駅に
「180%は…」と書くと、実際より混むように読めるためである。

**路線の最混雑区間の値である。**住む駅がその区間に入っているかどうかで、
読み手にとっての意味が変わる。門前仲町は東西線の最混雑区間（木場→門前仲町）に
入っており、毎朝その混み方の電車に乗ることになる。駅ページでは、
区間に入っている駅と入っていない駅を書き分ける。

数字を入れたことで、本文の事実誤りが3つ見つかった。

| 駅 | 書いていたこと | 実際 |
|---|---|---|
| 武蔵小山 | 目黒線は東横線ほど詰め込まれない | 目黒線133%、東横線124%で、目黒線のほうが混む |
| 六本木一丁目 | 南北線は他の地下鉄より混雑が緩い | 156%で、東京メトロ9路線の中では高いほうである |
| 六本木 | 日比谷線も大江戸線も都心のターミナルほどではない | 日比谷線163%は東京メトロでいちばん高い |

いずれも「混む／緩い」を数字なしで書いていたために気づけなかった。
**路線の混み方は印象で書かず、公表されている数字で書く。**

値が入らなかった15路線は、調査の対象に入っていない小規模な路線（都電荒川線、
東急世田谷線、東武大師線など）、複数の路線の線路を走る運行系統（湘南新宿ライン、
上野東京ライン、京王新線など）、公表資料の中で駅名が2行に折り返されていて
読み取れない路線（東京モノレール、日暮里・舎人ライナー、京急空港線）である。
**値は作らず、空のままにしている。**

#### 店の登録が足りない駅を見つける

`npm run check:coverage`（`scripts/check-store-coverage.py`）が、
乗降客数が同じくらいの駅と店の数を比べ、大きく下回る駅を並べる。

武蔵小山は1日43,946人が使う駅だが、300m以内の飲食店・酒場・カフェは19軒しか
登録されていない。同じ規模の駅の中央値は28軒である。
全長約800mのアーケード商店街がある駅の数としては少なすぎる。
大山（ハッピーロード大山商店街）は41,967人に対して7軒で、中央値47軒の15%だった。

**数は自動では補わない。**乗換だけに使われる駅（小竹向原）や、工業地帯・埋立地の駅は、
実際に店が少ないので同じように並ぶ。機械では区別できない。
このリストは、**本文に「店が少ない」と書く前に見るためのもの**である。

4軸のスコアそのものをどう補正するかは、まだ決めていない。
補正するには区ごとの実数が要るので、経済センサスの事業所数など、
別の出典を当てるところから始めることになる。

### 4.5 店の数でも乗降客数でも、駅前が繁華街かどうかを測れなかった

新大久保のファミリー適性が75点、静かさが50点に出ていた。駅から1,500m以内に
小中学校が40校、保育園と幼稚園が16園あり、地形も平坦だからである。
一方で荻窪はファミリー適性37点、静かさ37点だった。実態は逆である。

原因は2つあった。

**1. 施設の数は人口密度を測っていた。**新大久保の40校は、そこが
子育てに向くからではなく、人口密度が高いから多い。等々力は21校しかないが、
どちらが子どもと暮らしやすいかは言うまでもない。
そこで学校・園・公園・スーパーは「歩ける範囲にいくつかあれば足りる」ものとして数え、
足りたぶんから先は加点しないようにした（`saturate()`、§4.3）。

**2. 乗降客数は、駅を通り抜ける人の数でしかなかった。**
荻窪は1日21万人が乗り降りするが駅のすぐ外は住宅地で、新大久保は7万人だが
駅前は商業地域である。乗降客数で繁華街かどうかを判定すると、
荻窪のほうが繁華街だという答えになる。

駅から300m以内の店の数でも区別できなかった。OpenStreetMap に登録されている
飲食店と酒場は、荻窪が109軒、新大久保が53軒である。
新大久保の韓国料理店は大久保通りを東へ、職安通りを南へ広がっており、
300mの円に入りきらない。半径を500mまで広げると両駅とも180軒で並ぶ。
どこで切っても、この2駅の違いは店の数に表れない。

**警視庁の町丁別の認知件数が、この違いを分けた。**
駅から800m以内の町丁で、粗暴犯（暴行・傷害・脅迫・恐喝）の1町丁あたりの件数は
次のとおりである。

| 駅 | 粗暴犯（1町丁あたり・年） | 総合計 |
|---|---|---|
| 新宿 | 44.3 | 352.8 |
| 新大久保 | 36.2 | 233.5 |
| 大久保 | 30.5 | 199.5 |
| 六本木 | 10.0 | 44.5 |
| 北千住 | 7.0 | 42.7 |
| 高円寺 | 3.6 | 44.5 |
| 荻窪 | 2.5 | 25.9 |
| 西巣鴨 | 1.9 | 20.5 |
| 自由が丘 | 1.6 | 18.7 |
| 等々力 | 1.1 | 13.4 |
| 浜田山 | 0.6 | 11.8 |

新大久保は荻窪の14倍である。`scripts/fetch-crime.py` が、警視庁の公表値と
国土交通省の位置参照情報（町丁目ごとの緯度経度）を突き合わせて出す。
5,266町丁のうち5,113町丁を突き合わせられた。残りは「○○区計」のような集計行と、
23区外の島しょ部である。

認知件数は、そこに住む人が被害に遭う確率そのものではない。繁華街では、
そこで働く人や遊びに来た人が巻き込まれた件も同じ町丁に数える。
それでも「駅前がどういう場所か」を測る物差しとしては、
OpenStreetMap の店の数よりはるかに安定している。

組み直した結果、新大久保のファミリー適性は75点から13点、大久保は69点から13点、
高円寺は47点から37点になった。荻窪は37点から46点に上がった。
上位は祖師ヶ谷大蔵・井荻・戸越公園・中延・武蔵新田である。

**荻窪の静かさは37点のままである。**駅から300m以内に酒場が29軒・飲食店が80軒あり、
青梅街道が駅のすぐそばを通る。駅前の静けさとしては、この値が事実に合っている。
住む区画は駅前から離れるので、読み手の感覚と合わない可能性は残る。
住むエリアの静けさを測るなら、半径300mではなく500〜800mの帯で数え直すことになる。

### 4.6 用途地域を、駅前が商業地か住宅地かの物差しとして持つ

国土数値情報の A29「用途地域」から、駅から500m以内の面積のうち
商業地域・近隣商業地域・住居専用地域・工業地域がそれぞれ何割かを出している
（`scripts/fetch-zoning.py` → `data/computed/zoning.json`）。
容積率の平均も併せて持つ。

用途地域は都市計画法にもとづいて定めたもので、地図を作った人の多さにも
乗り換え客の数にも左右されない。

| 駅 | 商業地域 | 住居専用地域 | 容積率 |
|---|---|---|---|
| 新宿 | 100% | 0% | 829% |
| 東京 | 92% | 0% | 1,012% |
| 新大久保 | 31% | 11% | 394% |
| 荻窪 | 29% | 39% | 312% |
| 高円寺 | 23% | 47% | 294% |
| 自由が丘 | 10% | 64% | 211% |
| 等々力 | 0% | 72% | 157% |

いまは容積率だけを静かさとファミリー適性に使っている。
商業地域の割合と住居専用地域の割合は、まだスコアに入れていない。
新大久保の住居専用地域が11%と低いのは実態に合うが、
高円寺の47%は荻窪の39%より高く、この2駅の違いとは向きが合わない。
使い方を決めてから入れる。

## 5. 読み手の区分と重み

`src/lib/weights.ts` に定義。重みの合計は 1.0 に正規化される。

以前は `single` / `family` / `quiet` / `value` / `international` の5つを並べていた。
この5つは互いに重なっており、「単身で、かつ静かな街に住みたい」人が
どれを選べばいいか決まらなかった。そこで3つの軸に分け、組み合わせて8区分にした
（[14-audience-segments.md](./14-audience-segments.md)）。

| 選択 | 重く見る軸 |
|---|---|
| `kids`（子どもと住む） | ファミリー適性・治安・公園・買い物・病院・静かさ |
| `solo`（子どもなし） | 一人暮らし適性・都心アクセス・飲食店・カフェ |
| `out`（夜は街で過ごす） | ナイトライフ・飲食店・カフェ |
| `home`（夜は家で過ごす） | 静かさ・公園・治安 |
| `thrifty`（家賃の安さを優先） | 家賃の安さ・家賃コスパ・買い物 |
| `location`（立地のよさを優先） | 都心アクセス・乗換利便性・街のおしゃれさ |

区分は「18軸すべての重みづけ」ではなく「見る軸の選択」として扱う。
誰にとっても向きが同じ6軸（都心アクセス・浸水想定の小ささ・治安・買い物・病院・
乗換利便性）だけを低い重みで残し、残りは選んだ側が足したときだけ点数に入る。
全軸を1から始めた実装では、「夜は家で過ごす」を選んでも御茶ノ水が1位に出ていた。

総合評価（0–10）= Σ(score × weight) / 10。

**重みだけでは並び順が直らない。**区分が重く見る軸が下位3割に入る駅は、
一覧の後ろへ回す（`scoring.ts` の `rankBySegment()`）。理由は
[14-audience-segments.md](./14-audience-segments.md) §3.1 にある。

## 6. 適合度（逆引き検索）

勤務先からの逆引き検索の適合度は、スコアだけでなく**制約の充足**を含める。

```
適合度 = 制約フィルタ（通過 / 除外）× 重みつきスコア × 通勤ボーナス
```

1. **制約フィルタ**（満たさない駅は候補から除外）
   - 指定間取りの家賃相場 ≤ 家賃上限
   - 勤務先までの所要時間 ≤ 上限
   - 乗換回数 ≤ 上限
2. **重みつきスコア**: 選択した重みプリセット、または個別指定の重み。
3. **通勤ボーナス**: 上限に対して所要時間が短いほど加点（上限ぎりぎりより余裕がある方を上位に）。

出力には必ず「なぜ推すのか（高スコア軸）」「弱点（低スコア軸）」「似た候補」を添える（構想 §7）。
