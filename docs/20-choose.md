# 20. 条件に合わない駅を消していく道具

[06-roadmap.md](./06-roadmap.md) Phase 4.5 の1つめ「消去法で絞る」を作った（2026-11-07）。
ページは `/{locale}/choose`。トップページの入口に、勤務先からの逆引きと並べて置いている。

## 1. 何をする道具か

「この条件の駅は困る」という条件を1つずつ選ぶと、合わない駅が消えていく。
選ぶたびに残りの駅数を出し、結果の画面では条件ごとに「外すと何駅戻るか」を出す。

逆引き検索（`/work/[office]`）とは役割を分けている。

| | 逆引き検索 | この道具 |
|---|---|---|
| 何をするか | 条件を満たす駅を、合う順に並べる | 困る条件に当たる駅を消す |
| 0駅になったとき | 条件をゆるめる手がかりが無い | 条件ごとに、外すと何駅戻るかが分かる |

## 2. 画面の流れ

1. 質問に1つずつ答える（勤務先、通勤時間、乗り換え、家賃、大雨のときの浸水、高潮、暮らしの困りごと）。
   勤務先を選ばなければ、通勤時間と乗り換えの質問は出さない。どの画面でも、残りの駅数を上に出す
2. 結果の画面で、選んだ条件が並ぶ。条件ごとに「外すと何駅戻るか」と「この条件を外す」を出す
3. 条件は URL に載る。同じ条件のまま家族に送れる。URL を開くと結果の画面から始まる

## 3. 条件と、消える駅の数

住宅がほとんどない13駅を除く445駅が対象。数は2026-11-07のデータで、条件を1つだけ付けたとき。

| 条件 | 判定に使う値 | 消える駅 |
|---|---|---|
| 大雨のときの浸水の想定が3m以上の駅を外す | 駅の地点の浸水の深さ（`hazard.json` の `flood.atStation`） | 70 |
| 大雨のときの浸水想定区域に入る駅を外す | 同上。区域に入れば深さを問わず消す | 254 |
| 高潮の浸水想定区域に入る駅を外す | `hightide.atStation` | 136 |
| 坂が多い駅を外す | `terrain.json` の `slope` が `hilly` | 25 |
| 路線が1本だけの駅を外す | 使える路線の数 | 306 |
| 高速道路が近い駅を外す | 高速道路まで200m以内（`roads.json`）。本文の騒音の欄で音が大きいとする境目に合わせた | 66 |
| 粗暴犯などの件数が多いほうの2割を外す | 治安の点が20以下 | 34 |
| 通勤時間・乗り換え | `commutes.json` | 大手町40分以内で47 |
| 家賃 | 家賃相場の帯の上限（`rent-bands.json`） | 1K10万円以下で265 |

浸水は、区域に入るだけで消すと半分以上が消える。そこで深さで3段階（気にしない／3m以上を外す／区域内を外す）にした。

## 4. 判定できない駅は消さない

家賃の相場が出ていない駅や、浸水・地形のデータが無い駅は、その条件では消さずに残し、
駅ごとに「判定できない条件」として示す。消すと「条件に合わなかった」のか「データが無かった」のかが
読み手に分からなくなるため。地図データの登録が少ない駅の点を「測れていない」としたのと同じ考え方である
（`scripts/build-coverage-gaps.py`）。

## 5. 書き方で決めたこと

- 浸水の条件は「大雨のときの浸水」「高潮の浸水」と、何の浸水かを書く（ルール45）。
  駅の地点の想定で判定していること、想定しうる最大規模の雨を前提にした試算であること、
  住所が決まったら区のハザードマップで確かめることを、質問と結果の画面に添える（ルール32）
- 治安は警視庁の統計の件数として書き、「危険」「安全」と言わない
- 店の多さやにぎやかさのように、人によって好みが逆になるものは、消す条件にしない。
  残った駅は、勤務先を選んだときは通勤時間の短い順、選ばないときは総合評価の高い順に並べる

## 6. やっていないこと

- **チェーン店の名前で絞る**（Phase 4.5 の2つめ）。地図データの登録の細かさが区によって20倍違い、
  「登録が無い」と「店が無い」を区別できないため見送った。入れるなら、スーパーの名前に限り、
  「地図データに登録がある駅」と書いて、残す条件としてだけ使う
